# Task: JIRA-1234 — 订单审核增加信用额度校验

Status: `ready-to-implement`

## Requirement

- 审核订单前校验客户剩余额度。
- 额度不足时拒绝审核。
- 草稿保存逻辑保持不变。

## Current Behavior

`OrderApplicationService.approve()` 当前直接从 CREATED 进入 APPROVED，然后发起库存预留。

## Evidence

| Type | Location / Source | What it proves |
|---|---|---|
| code | `src/order/OrderApplicationService.java#approve` | 审核主入口及调用顺序 |
| code | `src/credit/CreditService.java#checkAvailable` | 已存在额度检查能力 |
| test | `tests/order/OrderApprovalTest.java` | 当前审核成功路径 |

## Execution Path

```text
OrderController.approve
→ OrderApplicationService.approve
→ Order.approve
→ OrderRepository.save
→ InventoryService.reserve
```

## Invariants

- draft/save 不应触发额度校验。
- 审核失败不能产生库存预留。

## Recommended Change

- Change point: `OrderApplicationService.approve()`
- Reason: 它拥有审核流程编排，并且额度校验与库存预留都属于审核前置动作。
- Scope: 在状态修改/库存预留前调用现有 `CreditService.checkAvailable()`。

## Risks

| Severity | Risk | Failure Scenario | Mitigation / Test |
|---|---|---|---|
| HIGH | 调用顺序错误 | 额度不足但已经占用库存 | 额度不足测试断言 inventory 未调用 |
| MEDIUM | 重复审核 | 并发审核导致额度竞态 | 保留现有并发/状态保护并做回归测试 |
